## How to Work with This Repository

### Making Changes
1. **Understand the context**: Review related files before making changes
2. **Preserve structure**: Maintain existing file organization and naming conventions
3. **Document additions**: New content should align with the AI/automation theme
4. **Test workflow code**: Any JavaScript/Worker code should be validated

### File Types and Handling
- **Text files (.txt)**: Documentation that can be edited with care to maintain formatting
- **HTML files**: Archived web content - generally should not be modified
- **JSON files**: Configuration data - modify with caution
- **Images**: Visual resources - do not modify unless specifically required
- **Log files**: Historical records - do not modify

### Code Standards
When working with code examples (like in `WorkFlowMastery.txt`):
- Follow modern JavaScript/ES6+ syntax
- Use async/await patterns for asynchronous operations
- Include clear comments for complex logic
- Ensure compatibility with Cloudflare Workers environment where applicable

### Testing and Validation
- This repository primarily contains documentation and reference materials
- For workflow code: Validate syntax and logic before committing
- For documentation: Review for clarity and accuracy
- There is currently no formal test suite in this repository.

### Best Practices
1. **Minimal changes**: Make only necessary modifications
2. **Context preservation**: Keep the repository's purpose and theme intact
3. **File integrity**: Don't accidentally corrupt HTML archives or images
4. **Meaningful commits**: Use descriptive commit messages
5. **Documentation first**: Update docs when adding new concepts or workflows

## Important Considerations
- This is a personal knowledge repository

- Git submodule paths and URLs are defined in the `.gitmodules` file; refer to that file when updating submodules
- Workflow code examples may reference specific environments (Cloudflare Workers)
